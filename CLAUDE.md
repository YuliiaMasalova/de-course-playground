# Project: Design Engineer Git

## Context
Це playground-репозиторій Юлії — UI/UX дизайнерки, яка практикується у верстці інтерфейсів на курсі з Data Engineering. Тут вона зберігає самостійні HTML-сторінки: приклади карток та UI-компонентів, зверстані на Tailwind CSS.

## Tech Stack
- **HTML5** — кожна сторінка/компонент це окремий самодостатній `.html`-файл
- **Tailwind CSS через CDN** (`<script src="https://cdn.tailwindcss.com">`) — без build-кроку, без npm/package.json
- Немає фреймворку (React/Vue/etc), немає JS-логіки, немає bundler'а (Vite/Webpack), немає TypeScript
- Немає тестів, лінтера, CI

## File Structure
```
/
├── index.html            # приклад картки на Tailwind (профіль)
├── obsidian-card3.html   # картка товару (Black Obsidian Stone)
└── README.md             # опис репозиторію (українською)
```
Кожен новий компонент/сторінка додається як окремий `.html`-файл у корені — спільних layout, head чи стилів між файлами немає.

## Code Conventions
- Один самодостатній HTML-файл на компонент: свій `<head>`, свій підключений Tailwind CDN-скрипт
- Верстка — **тільки utility-класи Tailwind**, кастомного CSS немає
- Активно використовуються **arbitrary values** (`w-[380px]`, `text-[26px]`, `bg-[#0D0D0D]`) замість стандартної шкали Tailwind
- Картка центрується на всю висоту екрана: `min-h-screen flex items-center justify-center`
- HTML-коментарі пояснюють секції розмітки (аватар, кнопки, опис) — мова коментарів і контенту не завжди однакова (є українська, є російська, є англійська)
- `lang` атрибут `<html>` виставляється під мову контенту конкретної картки (не завжди `uk`)

## What to do
- Тримати кожен компонент одним самодостатнім `.html`-файлом (легко відкрити й подивитись без збірки)
- Використовувати стандартну шкалу Tailwind (`p-4`, `text-2xl`, `rounded-2xl`) там, де підходить, і arbitrary values (`w-[380px]`) лише коли точне значення справді потрібне з дизайну
- Дублювати структуру існуючих карток (обгортка `bg-white/bg-[#1A1A1A] rounded-2xl shadow-lg p-8`) для візуальної консистентності нових карток
- Писати alt-тексти для зображень і зберігати семантичну структуру (`h1`/`h2`, `button` для дій)
- Комітити кожен новий компонент окремим PR/комітом з описовою назвою (як у наявній історії: "Add simple Tailwind CSS example page")

## What NOT to do
- Не підключати Tailwind CDN-скрипт кілька разів на одну сторінку і не змішувати з кастомним `<style>`/CSS-файлами
- Не переходити на build-тулінг (Vite, PostCSS-конфіг) без явного запиту — репозиторій навмисно без збірки
- Не залишати сирі URL на зовнішні картинки без перевірки, що вони стабільні/доступні (як `img.magnific.com` у obsidian-card3.html)
- Не змішувати мови в одному файлі без потреби (коментарі + контент однією мовою послідовно)
- Не додавати JS-фреймворки або залежності — це static-first playground, не production-застосунок
