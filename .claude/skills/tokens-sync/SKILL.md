# Skill: Tokens Sync

Автоматизує пайплайн design tokens: **Figma Variables → tokens.json → tokens.css → git commit**.

## Вхідні дані

Очікується посилання на Figma-файл (і опційно `node-id`) в аргументах виклику (`/tokens-sync <URL>`).

- Якщо URL не передано — запитай його в користувача. Не вигадуй і не використовуй URL з попередніх розмов без підтвердження, що він досі актуальний.
- Витягни `fileKey` з URL: `https://figma.com/design/:fileKey/:fileName?node-id=X-Y`. Якщо `node-id` вказано — це стартовий вузол; якщо ні — потрібно буде обійти сторінки через `get_metadata`, щоб знайти вузли компонентів (variables не витягуються з порожнього canvas-вузла напряму).

## Крок 1 — EXPORT (Figma → tokens.json)

1. `get_metadata` (без nodeId) → список сторінок; далі `get_metadata` по кожній релевантній сторінці/фрейму, щоб знайти конкретні вузли компонентів (frame/instance, не сам canvas — виклик `get_variable_defs` на порожньому canvas-вузлі впаде з помилкою "nothing selected").
2. Для кожного знайденого вузла компонента виклич `get_variable_defs(fileKey, nodeId)` — він повертає пласку мапу `"group/name": "resolved value"`.
3. Об'єднай усі мапи в одну, прибравши дублікати (однакова пара ключ→значення з різних вузлів — це нормально, компоненти шарять токени).
4. Перетвори кожен ключ на вкладену DTCG-структуру:
   - `"button/bg-default"` → `color.button.bg-default`
   - пробіли в іменах ("Horizontal padding") → kebab-case ("horizontal-padding")
   - визначай `$type` евристично: hex-рядок (`#rrggbb[aa]`) → `"color"`; чисто числове значення → `"dimension"` (додай `px`, якщо одиниці нема); рядок виду `Font(family: ...)` → `"typography"` (розбери на `fontFamily`/`fontWeight`/`fontSize`/`lineHeight`/`letterSpacing` як під-поля об'єкта `$value`); інше → `"string"`.
   - Figma MCP повертає вже **резолвнуті** значення, а не сирі alias-посилання — якщо в майбутньому з'явиться спосіб дістати справжній alias (наприклад, однакове ім'я з припискою `{group.other}`), онови формат; не вигадуй aliasи там, де їх нема.
5. Прочитай **існуючий** `tokens.json`, якщо він є, і зроби мердж, а не перезапис із нуля:
   - нові ключі з Figma → додай;
   - ключі з новим значенням → онови (`$value`, онови `$description` на актуальний коментар джерела);
   - ключі, яких **більше нема** у свіжому експорті з Figma — це кандидати на перейменування або видалення. Порівняй за значенням: якщо старий ключ мав те саме значення, що й новий ключ під іншим ім'ям — це, ймовірно, перейменування у Figma: онови ключ (не створюй дубль), онови всі $description.
   - якщо збігу за значенням нема (токен реально зник) — **не видаляй мовчки**. Зупинись, покажи список токенів-кандидатів на видалення і запитай підтвердження. Видаляй лише після явного "так".
6. Запиши оновлений `tokens.json` (стабільне сортування ключів, читабельний indent).

## Крок 2 — BUILD

1. Перевір, чи `style-dictionary` є в `devDependencies` (`package.json`). Якщо нема — постав: `npm install --save-dev style-dictionary`.
2. Перевір, чи є `style-dictionary.config.json` в корені. Якщо є — використай його як є (не переписуй сліпо). Якщо нема — створи мінімальний конфіг:
   - платформа `css` → `transformGroup: "css"`, `buildPath: "src/styles/"`, файл `tokens.css` форматом `css/variables`.
3. Запусти `npx style-dictionary build --config style-dictionary.config.json` (або дефолтний конфіг, якщо саме такий є в репо).
4. Переконайся, що build пройшов без помилок і `src/styles/tokens.css` (і `tokens.tailwind.js`, якщо платформа налаштована) реально оновились.

## Крок 3 — DIFF (показати ПЕРЕД комітом)

1. Виконай `git diff -- tokens.json src/styles/tokens.css` (і інші згенеровані файли, якщо є) і покажи його користувачу в чаті.
2. Дай коротке резюме: скільки токенів усього, скільки додано, скільки змінено значень, скільки перейменовано, скільки видалено (0, якщо нічого не видаляли).
3. Якщо є токени на видалення — це вже мало бути підтверджено в Кроці 1; тут просто відобрази фінальний список.
4. Якщо diff порожній (нема реальних змін) — повідом про це і зупинись, не роби порожній коміт.

## Крок 4 — COMMIT (push — тільки з підтвердженням)

1. `git add tokens.json src/styles/tokens.css` (+ `src/styles/tokens.tailwind.js`, `style-dictionary.config.json`, якщо їх щойно створено/змінено).
2. `git commit` з повідомленням:
   ```
   chore(tokens): sync from Figma

   Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>
   ```
3. **Не роби `git push` автоматично.** Покажи хеш і резюме коміту та запитай користувача, чи запушити в поточну гілку (`git push`). Пуш — дія, видима іншим і важко відмінна, тож виконуй її лише після явного "так" у цьому виклику, навіть якщо весь інший пайплайн автоматизований.
4. Ніколи не використовуй `git push --force` в рамках цього скіла.

## Фінальний звіт

Коротко, після кожного запуску:
- Скільки токенів усього в `tokens.json`.
- Додано: N (перелічи ключі).
- Змінено: M (ключ → старе значення → нове значення).
- Перейменовано: K (старий ключ → новий ключ).
- Видалено: L (тільки якщо підтверджено користувачем).
- Хеш і повідомлення коміту; запушено чи ні (і чому, якщо ні).

## Заборонено

- Не видаляти токени з `tokens.json` без явного підтвердження користувача в поточному виклику.
- Не переписувати `style-dictionary.config.json` з нуля, якщо він вже існує — тільки доповнювати за потреби.
- Не робити `git push` без явного "так" від користувача в цьому ж виклику; ніколи не форсити пуш.
- Не комітити, якщо diff порожній.
- Не вигадувати Figma URL, node-id чи значення токенів — усе має походити з реального виклику Figma MCP.
